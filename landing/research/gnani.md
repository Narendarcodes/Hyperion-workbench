# gnani.ai — Landing Reference

**Observed:** 2026-09-09 using live browser inspection.

## Evidence
- Display type: `Gambarino`, 400. Hero H1: 80px / 80px at desktop.
- UI type: `Inter`, 14px / 21px in inspected body and navigation.
- White-led canvas (`rgb(249,250,251)` body) with black/grey text.
- GSAP + ScrollTrigger detected. No Lenis/Three.js detected.
- Narrative order: hero → instant product interaction → model family → proof/scale → outcomes → product platform → data/privacy → FAQ → CTA.

## Steal
| Pattern | HYPERION application |
|---|---|
| One strong editorial display face against an understated UI face | Use Archivo display + IBM Plex Sans UI; preserves an engineered rather than lifestyle tone. |
| Clear capability taxonomy early in the story | Give local intake, RAG, router, bounded tools, sandbox, and deliverables named capability surfaces. |
| Product interaction shown as evidence rather than decorative illustration | Make the sovereignty monitor and operating-model trace the page's proof surfaces. |
| ScrollTrigger section choreography | Use one pinned operating-model sequence; keep all other reveals restrained. |

## Skip
- Their white editorial canvas conflicts with the approved dark-navy Hyperion brand.
- Scale metrics and enterprise proof are not transferable: HYPERION has no public deployment figures to claim.
- Inter is disallowed by this project's design direction.
- Voice-AI demo interaction does not map to an industrial evidence workbench.

**Verdict:** Borrow narrative clarity and editorial hierarchy, not the palette, font, or proof strategy.
